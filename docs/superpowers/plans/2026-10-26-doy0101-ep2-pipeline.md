> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the existing EduBío 360 backend demonstrate IE1–IE5 through an auditable, security-gated GitHub Actions workflow and Docker Compose simulation.

**Architecture:** Preserve the eight-module Java 21 Maven reactor, the existing test coverage and Compose smoke script. Add Snyk and Dependabot checks, harden container runtime settings, and make the CI job graph explicit: verify → security → image build → simulated deployment and evidence.

**Tech Stack:** Java 21, Spring Boot, Maven, JaCoCo, Docker BuildKit, Docker Compose, GitHub Actions, Dependabot, Snyk CLI, Python `unittest`/PyYAML for configuration tests.

## Global Constraints

- Use the rubric for **DOY0101**, not the other course's JVY0101 rubric in this repository.
- Do not alter business endpoints, database volumes, or microservice inventory.
- Never commit tokens, passwords, rendered reports or student reflections.
- `SNYK_TOKEN` is a repository secret created by the students; workflows fail safely if it is missing on trusted events.
- Docker Compose deploy is ephemeral in GitHub-hosted runners and must be documented as a simulation.
- Keep repository `main` untouched until branch tests and review are complete.

## Review Focus

- Missing `SNYK_TOKEN` on a trusted push must yield a clear failure and block downstream deployment (Task 1 test).
- Vulnerabilities above threshold or scanner errors must not be masked by `continue-on-error` (Task 1 test).
- External fork PRs/Dependabot events must not receive sensitive tokens or deploy (Task 3 test).
- Java service ports/healthchecks must agree with existing `application.yml`, while resource limits remain feasible on the runner (Task 2 test).
- Simulated deployment must collect logs after a smoke-test failure without falsely reporting a success (Task 3 test).
